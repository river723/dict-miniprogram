## 修复：页面内图标渲染成「豆腐块 + 字母」（用户反馈）

**现象**：home 页「继续学习」按钮等页面内图标显示为「符号 + 字母」，tabBar 却正常。

**根因**：`build_icons.py` 用 `"'%s': '\\u%04x'"` 生成 `theme/icons.js`。
MaterialCommunityIcons 的码位是 **5 位十六进制**（如 `f0708` = U+F0708，补充平面 SPUA-A），
而 **JS 的 `\uXXXX` 转义只吃 4 位** —— `'\uf0708'` 被解析成 `U+F070` + 字符 `'8'`，
U+F070 不在子集字体里 → 渲染成豆腐块，后面跟着一个 `8`。166 个图标**全部中招**。

**修复方案（两步合一）**：把字形码位统一重映射到 **BMP 私有区 U+E000–U+E0A5**。
- 一处解决转义问题（4 位天然合法）
- 同时规避补充平面字符配合 WebView 自定义字体渲染的机型兼容问题
- 实现：subset 前记 `glyphmap[n] -> glyph name`，subset 后就地重建 cmap
  （`CmapSubtable.newSubtable(4)`，platformID 3 / platEncID 1），再 `save_font`
- `cp_of` 是唯一映射源：`icons.js`、`icons.wxs`、tabBar PNG 三处必须同步（脚本已统一）

**校验（新增 `.workbuddy/_verify_icons.py`，独立于生成脚本）**：
- 每个新码位都能在字体 cmap 里解析到字形；渲染无空图
- **归一化图像比对**：渲染→裁到墨迹→归一到 32×32→MAD。当前 **平均 1.58 / 最大 12.5**（噪声级），
  即与 App 原字体视觉等同
- 输出 `preview/icons_before.png` / `icons_after.png` 两张 166 图标网格图，肉眼逐格一致

**防回归**：`check_syntax.cjs` 新增断言 —— `icons.js` 里码位必须全部落在 BMP 内
（同时覆盖 `\uXXXX` 转义与直写字符两种形式），违反即 `icon_warnings` 报错。

**改动的文件**：`.workbuddy/build_icons.py`、`miniprogram/theme/icons.js`、
`miniprogram/theme/icons.wxss`（新 TTF base64，20KB）、`miniprogram/utils/icons.wxs`、
`miniprogram/assets/icons/tab-*.png`（8 张重渲）、`.workbuddy/check_syntax.cjs`。

### 环境备忘

  **一律用 PowerShell**；PowerShell 的 stdout 在本会话里抓不到，命令输出要 `| Out-File` 后再用 Read 读。
