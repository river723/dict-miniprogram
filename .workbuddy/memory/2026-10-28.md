## 用户提问「是否应该有个登录功能来判断管理员」→ 结论：**不需要做登录功能**

关键认知（小程序与 App 的根本差异）：
- 小程序用户**已经登录了微信**，`wx.login` 走的是静默授权，用户无感。
- 云函数里 `cloud.getWXContext().OPENID` **由微信平台自动注入，前端无法伪造**，
  且项目里 `words` 云函数已经在用（按 `_openid` 隔离用户数据）→ **身份层已经免费具备了**。
- 所以**缺的从来不是「登录/认证」，而是「授权/角色」**：即「这个 OPENID 是不是管理员」。
- 真做「登录功能」（手机号+密码/验证码/昵称头像/自建账号体系）属于过度设计：
  要维护 session、要过审、要处理找回密码，还要新增隐私政策 —— 而这些解决的
  不是当前问题。微信生态里身份是**平台给的**，不是自己造的。

### 推荐方案（openid 白名单 + 前后端双锁）
1. **云函数层（安全底线，必须做）**：`seed` / `contentseed` 入口取 `OPENID`，
   不在白名单 → 直接 `return { ok:false, error:'FORBIDDEN' }`，**一行都不执行**。
   前端传的任何东西都不可信，鉴权只能在服务端。
2. **前端层（体验 + 纵深防御）**：settings 页异步取 `isAdmin`（如 `admin` 云函数
   或 `words` 加一个 `whoami` action）；非管理员隐藏「词库初始化」按钮；
   `seed` 页 `onShow` 再校验一次，不通过 `navigateBack`。
3. **白名单存哪（3 选 1）**：
   - 写死常量 `const ADMIN_OPENIDS = ['oxxxx']`（最简单，改名单要重部署云函数）
   - 云函数环境变量 `ADMIN_OPENIDS`（改不用重部署，但要控制台改）
   - 建 `admins` 集合存 openid 文档（最灵活，可多人、可随时增删；
     但集合权限要设为**仅管理员可写**，否则用户能自己把自己加进白名单 ⚠）

## ✅ 管理员鉴权落地（用户提供了自己的 openid —— 明文不入库，只存 sha256 指纹）

### 做了什么
**三层闸门**：
1. **云函数入口（真闸门）** —— `seed` / `contentseed` / `setup` 三个云函数的 `exports.main`
   开头取 `getWXContext().OPENID` → `isAdmin()` 判定 → 不通过直接 `return forbidden(...)`，
   **一行都不执行**。判定在 `switch (event.action)` **之前**，无法绕过。
2. **前端隐藏** —— `settings.wxml` 的「词库初始化」按钮包 `wx:if="{{isAdmin}}"`；
   `settings.js#goSeed` 再校验一次。
3. **页面兜底** —— `seed.js` 的 `onShow` 走 `checkAdmin()`，路由是公开的（可被直接跳转/分享进入）；
   `seed.wxml` 用 `adminState` 三态（checking / denied / ok）控制渲染。

**新增 `admin` 云函数**（身份自证 + 白名单管理）：
- `whoami` —— 任何人可调，返回 `{ openid, isAdmin }`（前端据此决定显不显示入口）。
- `grantAdmin` / `revokeAdmin` / `listAdmins` —— 仅管理员；加减 `admins` 集合，
  **立即生效、不用重部署**（改内置指纹则要重部署）。
- `ensureCollection` —— 幂等建 `admins` 集合。

**新增 `services/admin.js`（前端）**：`fetchAdminState` / `peekAdminState` / `clearAdminCache`，
内存 + 存储双缓存，TTL 5 分钟。查不到一律 `isAdmin:false`（fail-closed）。

### 关键设计决策
- **白名单存 sha256 指纹而不是 openid 本身** —— 仓库是公开的，openid 虽非密钥、却是个人标识；
  sha256 不可逆推（openid 熵约 166bit）。指纹 `39a680308f98e13c7a986a1cdc7f20ee0a7e47a53f7d523296f3cb84e56d8807`。
- **内置指纹 = 零配置**，顺带解开了「建 admins 集合需要管理员，而建 admins 集合本身就是
  管理员操作」的**鸡生蛋问题** —— 开发者本人不依赖集合是否已建好。
- **只读云函数不加闸门**：`worddict`/`content`/`tts` 数据本来就是所有用户可读的公开词库，
  加了只会让正常用户查不到词。真正危险的只有能写全局共享集合的三个。
- **空 OPENID 一律拒绝**（fail-closed）：控制台「云端测试」没用户上下文 → FORBIDDEN，
  属预期，请在真机验证。刻意如此 —— 防将来给这些函数开 HTTP 访问服务（同样无上下文）漏出缺口。
- **`admins` 集合权限必须「所有用户不可读写」**：云函数服务端 SDK 不受限，客户端 SDK 完全碰不到
  → 普通用户无法自己给自己发管理员。误设成可读 = 后门。

### 云函数副本机制（本次新踩的坑）
云函数各自独立打包上传，**运行时无法 require 兄弟目录的文件** → 需要鉴权的云函数各存一份副本。
- 权威源 `scripts/lib/admin-guard.cjs`（**必须 .cjs**：根 `package.json` 是 `"type":"module"`，
  根下 `.js` 会被当 ESM；但云函数目录下的 `package.json` 无 `type`（= CommonJS），
  所以**副本在云函数里必须叫 `admin-guard.js`** 才能被 `require('./admin-guard')` 解析）；
- 接线脚本 `.workbuddy/admin_wire.cjs`（`--apply` 写入 / 不带则只检查，差异时非 0 退出）；
- 回归 `_smoke_admin.cjs`（**54 项全过**）含「四份副本字节一致」断言，防漂移。

  自动转成绝对路径（`C:/Users/.../PortableGit/`），这是本次踩坑的隐藏放大器。
- 未知函数名 → **显式报错退出**（非静默跳过）：静默跳过会让人以为部署过了。
- 只给分隔符没给名字 → 报错，避免误触发全量部署。
- 新增 `--dry` 干跑模式：只解析参数不调 CLI，用来验证命令写法。

## ✅ 集合权限设置 —— 修正官方选项名 + 加权限自检

### ⚠ 关键修正：我之前给的措辞是错的
用户问「如何把 admins 集合权限设为『所有用户不可读写』」→ **控制台里没有这个选项**。
官方基础权限只有四种，准确名称是：
- 仅创建者可写，所有人可读
- 仅创建者可读写
- 仅管理端可写，所有人可读
- **仅管理端可读写**  ← admins 集合要的就是这个

「所有用户不可读写」是**自定义安全规则** `{ "read": false, "write": false }` 的等价描述，
在基础权限下拉里找不到 → 用户会反复找不存在的选项。
已把「仅管理端可读写」写进代码注释、setup 云函数、docs、MEMORY.md。

### 📌 重大发现：前端 0 处直连数据库
`grep 'wx.cloud.database' miniprogram/` = **0**，全部走云函数（callCloud 调 8 个函数）。
→ **所有**集合都应该是「仅管理端可读写」，不需要任何「所有人可读」的集合。
（之前 setup 里的注释写着 worddict「需所有用户可读」，是过时且多余的开洞。）

### 新增：集合权限自检（`miniprogram/services/permCheck.js`）
集合权限在控制台点，**点错不会报错**，只在真有人越权时才暴露 → 必须能主动验。
- **必须在客户端跑**：云函数用服务端 SDK，管理端永远有全权限，测不出来；
  只有小程序客户端 SDK 会被权限规则拦截（错误码 -502003）。
- 对每集合做读 + 写两次探测 → 三档：
  `locked` 读写都被拒 ✓ / `readable` 读成功 ✗ / `writable` 写成功 ✗（严重后门）。
- ⚠ 写探测会真插一条测试文档（带 `__mg_perm_probe` 标记），成功后**立刻删除**，
  删不掉会返回文档 ID 供手动清理。
- 入口：小程序「设置 → 安全自检 → 检测集合权限」（仅管理员可见）。
