## 追加 2：答题页全白（只剩导航栏标题"答题"）

**根因：`exam-answer.js` 把同步方法当 Promise 用。**

```js
StorageService.getSettings()      // storage.js: const getSettings = () => {...} —— 同步，返回对象
  .then((s) => ...)               // TypeError: .then is not a function
```
→ 抛在 `onLoad` 里 → `setData({ready:true})` 与 `render()` **都没执行** → `ready` 停在 `false`；
而 `exam-answer.wxml` 里**所有内容都挂在 `wx:elif="{{ready}}"` 上**（`empty` 分支同样是 false）
→ **整页什么都不渲染，只剩导航栏标题**。与用户描述的"下面全是空白"完全吻合。

修复三处：
1. `getSettings()` 改同步读取（全项目唯一误用点；`exam-setup.js` 的用法本来就是对的）。
2. `onLoad` 包 `try/catch` —— 初始化异常落到 `empty` 态 + toast，**不再白屏**。
3. `render()` 里 `q` 为空时走 `empty` 态（防草稿污染 / 下标越界）。

已用 **multiline** 正则全项目扫描 `StorageService.<同步方法>().then` → **无其他同类问题**
（单行正则会漏掉跨行写法，这类扫描必须开 multiline）。

### 教训（可复用的排查方法论）

- **"页面只剩标题"＝ `onLoad` 中途抛异常**，而不是数据为空 —— 数据为空会走 `empty` 分支、
  显示"没有题目"。**先看页面是不是有个 `ready`/`loaded` 开关把所有内容都包住了**，
  再顺着 `onLoad` 逐行找会抛异常的那一行。
- **`storage.js` 同步/异步是混着的**：`get*` 基本同步（读本地缓存），
  `add*/update*/delete*/save*/pullAll/flushDirty` 基本 async（要上云）。
  调用前先确认目标方法是 `const x = () =>` 还是 `async function x()`。
- 防御：凡是"整页内容挂在某个 ready 标志上"的页面，`onLoad` 都应包 `try/catch`
  并落到**可见的错误态** —— 白屏是最难定位的一类 bug，成本全花在排查上。

### 方法论沉淀

- **核实成本类数字的标准动作**：① 量实际 prompt/输出规模（抽函数源码跑，不靠估）
  ② 查**当前**单价（大模型价格变动极快，必须带 freshness 过滤）
  ③ 区分**固定成本 vs 边际成本**（套餐内的配额不能算进单用户成本）
  ④ 交叉验证总数与分项是否自洽 —— 防止"错误互相抵消"。
- 成本测算脚本模板可复用：抽 `ai/index.js` 的 build* 函数（避开 wx-server-sdk）
  + 中文按 0.6 token/字、英文按 1.3 token/词的估算函数。

## 追加 3：真机主题不受控（设置浅色却显示深色）

**症状**：真机上无论设置里选什么都是深色；开发者工具里恒为浅色。

### 根因：两个独立缺陷叠加

1. **深色变量挂在 `@media (prefers-color-scheme: dark)` 上** —— 媒体查询只看**系统**主题，
   不看 App 内设置。真机系统深色 → 无条件命中；开发者工具默认不模拟深色 → 恒不命中。
   → 这正是"工具正常、真机变深"的来源，也是`app.json` 没开 `darkmode` 也会中招的原因
   （原代码注释里"不开 darkmode 就不匹配"的假设是**错的**）。
2. **`settings.theme`（light/dark/system）全项目只存不读** —— 设置页写进去、profile 页读出来
   显示文案，**没有任何地方消费它** → 是个假开关。

### 修法：媒体查询换成受控作用域类

- `theme/theme.wxss`：深色变量从 `@media` 块改为 **`.mg-theme-dark { ... }`**。
- 新增 `miniprogram/utils/theme.js`：`resolveDark(settings)` 按 档位+`getSystemInfoSync().theme`
  判定；`applyTheme(ctx)` 写入 `themeClass` 并同步窗口底色/导航栏色（`lastApplied` 去重）。
- 30 个页面批量接线：根 view → `class="mg-page {{themeClass}}"`，`onShow` → `applyTheme(this)`
  （脚本 `.workbuddy/_theme_wire.cjs`，支持 `--apply`，新增页面可复用）。
- settings 切换后 **立即生效**（`invalidateTheme()` + `applyTheme(this)`），不用等返回页。
- `app.js` `onLaunch` 先 `initThemeWindow()`，避免深色下首屏闪一下浅色。

### 三个踩到的坑

- **根 view 必须自带背景**。深色变量挂在根 view 上，而 `page` 元素的背景仍解析为浅色
  → 根节点没有 `background` 的页面（`review`/`seed` 的 `.page`）会露出浅底深字。
  `exam-practice` 的 `.rep` 自带 `var(--mg-bg)` 所以没事。**新增页面一律用 `.mg-page`**。
- `wx.setNavigationBarColor` 是**全局**的，会覆盖各页 json 配置。本项目所有页都是
  `#2E5E4E`/白字，统一设置无副作用；将来若有页面自定义导航栏色要单独处理。
- **tabBar 无法运行时改色**（微信限制）。唯一途径是 `darkmode:true` + `theme.json`，
  但那样只跟随**系统**、不跟随 App 内设置 → 会让"设置浅色"再次失效。**故不开**，
  深色下 tabBar 保持白底属已知瑕疵。

### 复用判断依据

先量化变量化程度再决定值不值得做：`var(--mg-*)` 引用 **1047** 处 vs 页面硬编码约 **57** 处
（≈95%）→ 深色 token 其实早已铺好，只差一个开关 → 值得做完整三档，而不是简单禁用深色。
