## 故事章节只显示译文、不显示英文原文（重要坑）

**现象**：`story-read` 章节正文里，中文译文正常，英文原文整段不渲染。

**排查**：数据侧完全正常 —— 离线实测 `buildBilingualPairs` 42 段英中 1:1 配对无空段，
`markWords` 的 seg 拼接能精确还原原文（431=431），241 个目标词、正则 1888 字符也都没问题。
所以问题 100% 在渲染层。

**根因**：`.sr__en` 是 `<text>` 标签，却被设成 **`display: block`**。
微信的 `text` 是行内元素，只有 `display:inline` 时正常；设成 `block` 后，
**内部「文本 + `wx:for` 生成的多个子 `<text>`」混排会整段不渲染**。
（同页的 `.sr__zh` 也是 `block` 却正常，因为它**没有子节点**、是纯文本 —— 这正好解释了"只有译文能显示"。）

**修复**（两处页面同一模式，一起改了）：
- `pages/story-read/story-read.wxss`、`pages/article-read/article-read.wxss`：
  `.sr__en` / `.ar__en` 由 `display:block` 改 **`display:inline`**，换行交给外层 `.sr__para`（view）。
- `.wxml`：内层 `wx:for` 的 `<text>` 外面包一层 **`<block wx:for>`**
  （避免 `wx:if` + `wx:for` 同时挂在嵌套 text 上），`user-select` 从外层 text 移到内层。

**通用经验（写进约定）**：
- 小程序里 **`<text>` 一律不要设 `display:block`**；需要块级效果就外面套 `<view>`。
- `<text>` 内做"多节点混排"时，用 `<block wx:for>` 包内层 `<text>`，不要直接在外层 text 上挂 `wx:for`。

### 二次修复（第一版没解决）

用户反馈改完后**仍然只显示目标词、英文原文不显示**（且目标词本来就不需要单独列出）。

- 实测 `markWords` 输出：第 1 段 15 个 seg，7 个 `hit:true`（=目标词）、8 个 `hit:false`（=普通文本）。
  **现象规律 = 只有 `hit:true` 的段渲染出来**，普通段全丢。
- 之前那版仍把外层写成 `<text class="sr__en">` 里嵌 `wx:for` 的子 `<text>` —— **text 嵌套 text**
  才是最可疑的点（`hit:false` 时 class 为空串，也可能一并受影响）。
- **最终采用的稳妥结构（推荐作为本项目标准写法）**：
  - 外层改用 **`<view class="sr__en">`**（view 可自由 `display:block`，无 text 嵌套限制）；
  - 内层只放**叶子 `<text>`**，`wx:for` 直接挂在这个 text 上，class 固定带一个基类
    （`class="sr__seg {{item.hit ? 'is-hit' : ''}}"`，**不要出现空 class**）；
  - 基类 `.sr__seg` / `.ar__seg` 显式声明 `font-size/line-height/color`，不依赖继承。
- 同步改了 `article-read`（`.ar__seg` + 外层 view）。
- 教训：**小程序里"文本按关键词切段再拼回"这种需求，外层容器用 `view`、内层叶子用 `text`，
  不要用 text 包 text**。第一版只改 `display` 是没抓住重点。


### 三次修复 —— 真凶终于找到（前两次方向都错了）

用户第三次反馈"还是只显示目标词、不显示原文，目标词无需显示"，于是**停止 CSS 层面的猜测**，
回到数据层用探针实测，一次命中：

```
para[0]  en(typeof=undefined)  zh(typeof=string)  segs(isArray=true,len=15)
```

**真因**：`miniprogram/utils/story.js` 的 `buildSegments()` 只返回 `{ segs, zh }`，
**压根没有 `en` 字段**。WXML 用 `wx:if="{{para.en}}"` 判断是否渲染英文段落，
`para.en` 恒为 `undefined` → **整段英文永远不渲染**。译文那段 `wx:if="{{showTranslation && para.zh}}"`
用的是真实存在的 `zh`，所以译文能显示 —— 现象完全吻合。

也就是说：前两次改 CSS（`display` → `view` 包裹）**方向全错**，真凶在数据构造。
（那次"只有 hit:true 的段渲染"的观察其实是误判：译文分支显示的是 `zh` 本身，
不是被高亮的英文片段。）

**修复**：
- `utils/story.js#buildSegments` 补 `en: p.en || ''`。
- `pages/article-read/article-read.js` 的 `buildPairs` 补 `en: line`，`.map` 补 `en: p.en || ''`
  （同一个坑，一起堵上）。
- 顺手加固 `utils/article.js#markWords`：入参 `plain` 为空/非字符串时先 `String(plain == null ? '' : plain)`，
  且 `list.length === 0 || !text` 时返回 `[{ text, hit: false }]`（原版空串会返回 `text: undefined`）。

**验证（探针，真实数据 `../memo-grad/src/data/stories.json` 前 5 章）**：
```

en 非空段落: 249 / 249
segs 拼接还原 en: 249 / 249
```

**构建函数返回的对象字段，必须和 WXML 里 `wx:if` 引用的字段对齐。**
