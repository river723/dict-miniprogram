## 雅思页显示考研词表（真 bug，判据设计缺陷）

- **现象**：用户报 `fusion / enzyme / estuary / cuisine / adept` 等雅思独有词在雅思库搜不到。
- **排查**：数据在包里（fusion 索引 1776），端到端复现搜索逻辑**能命中** → 界面取的不是那份数据。
- **根因**：`ensureLocalCloudDecision` 只比数量（`云端count >= 本地count`）。`worddict` 云函数
  当时**未重部署**，线上旧版不认识 `lib`，恒查考研集合返回 **4801**；
  而 `4801 >= 4491` → 判定「云端更全，切云端」→ **雅思页整个显示成考研词表**。
  两个集合数量太接近，数量判据天然分辨不出来。
- **修法**：不信数量，信身份。云函数所有 return 加 `col: COL`（5 处）；
  服务层加 `CLOUD_COLLECTION` + `staleCloud`；前端校验 `col === CLOUD_COLLECTION[lib]`。
- **两个连带坑**：
  ① `staleCloud` **不抛错**，try/catch 兜不住 → 页面必须显式判并 throw 进既有兜底分支；
     回落时还要清 `_localUseCloud=false`，否则本会话后续查询继续走坏的云端。
  ② `countWorddict` 返回值 number → `{total,col}`，调用方 `dictionary.js` 同步改解构。
- **验证**：check_syntax 全 0 错；`_smoke_find.cjs` 30 项全过（三种云端状态判定 + 11 个雅思独有词搜索 + 词表关系锁定）。

## 音标全量补齐（承上次中断的 ECDICT 线）
**起因**：网络恢复后完成 ECDICT 抓取，却查出比"19 词无音标"更严重的问题 ——
**eudic 对 34 个词给的是 KK 字体编码而非 IPA**（`5`=ˈ `E`=eɪ `I`=ɪ `Q`=ʌ `N`=ŋ `F`=ʃ `^`=次重音），
页面显示成 `in5hibit`/`sfiNks`/`tB:`；另 8 条带未剥的 `(US)` 前缀。
上轮「补回 23 词音标」补的是编码原文，**等于没修**。

**数据源突破**：GitHub ECDICT 官方源全拿不到（raw 是 git-lfs 指针 / release zip 404 / API 403），
**npm 镜像 `registry.npmmirror.com/cdict_query` 可用**（tarball 4.2MB，内含 SQLite 56992 词条）。
用 Node 22 内置 `node:sqlite` 的 `DatabaseSync` 读，**不必装 sqlite3**。

**产出** `_tools/fix_phonetics_from_ecdict.cjs`（默认预览，`--apply` 写入）：
ECDICT 覆盖 42 + 人工 OVERRIDES 11 = **53/53 全解，无音标词归零**。

**归一化踩的 4 个坑**：
1. 剥前导尾缀时**不能碰 `:`** → 否则 `tar 'tɑ:'` 丢长音号（第一次就踩了）。
2. ECDICT 重音符**位置不可靠**（`misgiving 'mis'^iviŋ` → 词中重音 `ˈˌiviŋ`）→ 只留词首第一个。
3. 英式拼写在美式词典查不到 → variants 试 `-ise→-ize` / 双写辅音还原 / 去连字符（救回 jeopardise）。
4. **别把「多读音条目」（`ˈkɔːdʒəl, ˈkɔːdiəl`）当坏数据** —— 曾顺带清尾分号误伤 7 个正常条目，
   判据收紧为「空 / 含 [0-9A-Z^] / 以 (US)|(UK) 开头」三类。

**校验**（严格 diff，基线取 git HEAD）：4491 词数不变、53 处变更**逐条确认只动 ph**（d/f/k 全等）、
KK 残留 0、无音标 0。回归 30 项全过；check_syntax 52 JS/35 JSON/33 WXML/36 WXSS 0 错 0 警；
主包 993KB/2048KB。ECDICT 二进制已入 .gitignore。

**记忆维护**：MEMORY.md 超限（23.9K）→ 精简到 15.2K，2026-09 早期日志要点并入后删除。

## 雅思词库云端化方案（用户提出 → 评估 → 落地第一步）
**用户诉求**：雅思库应与考研库同等地位放云端；信息不全就用考研库补齐，其余另补；音标雅思自带、考研不考虑。

**评估结论（实测数据）**：方案可行，但「复用」不能整条搬。
- 交集 2753/4491（61%），富词条字段 **100% 完整**（例句/词源/形近词/记忆技巧）→ 复用零成本零幻觉
- 雅思独有 1738（39%）考研没有 → ECDICT 只能给释义音标，例句词源须 AI（约 ¥2.36）
- ⚠ **难度差 ≥2 星 773 词（28%）、考频差 ≥2 星 217 词（8%）** → 整条搬运会污染雅思重标口径
- 另有 2043 个考研独有词未纳入（用户决定**先不扩**，维持 4491）

**用户拍板**：① 考频难度保留雅思自己重标的 ② 1738 独有词调 AI 补齐 ③ 暂不扩词表。

**已落地**：
- `gen-ielts-rich.mjs` 的 `toDoc` 改为**只从考研取内容字段**，f/k/音标强制走雅思侧；
  AI prompt 移除 frequency/difficulty（模型拍的不可信），validate 不再校验；新增 `--rebuild`。
- 按新口径 `--rebuild --reuse-only` 重建 2758 条：diff 显示 **18 处音标修复（5 条 (US) 脏值
  + 13 条补空）、f/k 零变化、内容字段零变化** —— 证明旧产物本就雅思口径，改动是防未来回归。
- 新增 `.workbuddy/_smoke_ielts_rich.cjs`（22 项），含 3 条反向断言（f/k 须等于雅思值、
  释义复用率 ≥95%、f/k 与考研差异率 >50% 证明没被搬运）。

**踩的坑**：① 脚本正则里写 `\"` 被 JS 当转义引号吃掉 → 整条正则失配、Map 变空（用 python 精确替换）；
② `| grep -v Warning` 会吞掉含 Warning 的输出行，导致内联 `node -e` 的比较结果被误读 ——
**验证逻辑一律写临时文件跑，别用管道内联**；③ 例句含词校验从 75 例误报降到 0 需三级规则。
