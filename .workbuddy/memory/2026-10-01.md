## 替换系列故事（星际漫游者 → 南苑九十天）

### ⚠️ 关键坑：新数据带 Markdown 粗体标记，旧数据不带

新旧数据的**消费形态不同**，直接替换会让正文渲染出字面星号：

| | 旧数据（星际漫游者） | 新数据（南苑九十天） |
|---|---|---|
| `**` 标记 | 几乎没有（10 个，1/20 章） | **9237 处，20/20 章** |
| 高亮来源 | 纯靠 `words` 列表，`markWords(p.en, words)` 正则匹配 | 写作时人工标了 `**word**` |

而 `utils/story.js` **不做任何 `**` 剥离**（它只调 `markWords`）；`utils/article.js#parseArticle`
虽然会剥，但**故事页根本不走它**（那条路是 article-read 文稿页的）。所以直接替换 = 每章正文
满屏 `**privilege**`。**这是本次最重要的发现。**

清洗规则（`scripts/normalize-stories.mjs`，新增，已注册 `npm run stories:normalize`）：
```js
s.replace(/\*{3,}/g,'')        // ① 先吃 3+ 连续星号：***x*** / ****x****
 .replace(/\*\*/g,'')          // ② 再吃成对粗体
 .replace(/\*(?=[^*]*\*)/g,'') // ③ 再吃成对斜体
 .replace(/\*/g,'');           // ④ 兜底孤立星号
```
顺序不能反 —— 若只按 `**` 两两替换，`***x***` 这类**奇数个星号**会残留孤星
（全库共 187 个 3+ 连星号 / 12 处畸形标记，如 `***questionnaire***`、`****继续****`）。
另有 895 个**单星斜体**（`*probably ignored*`、`*Public reading facilities shall be preserved.*`），
一并清掉（旧数据无斜体先例，星号承载不了斜体语义）。
结果：星号 78635 → 0，40 个字段被改写。

### 三个破坏性问题

1. **`words` 从 string[] 变 object[]**（`{w,pos,zh,tip,role,field}`）。
   `article.js#markWords` 执行 `String(w)` → 得到 `"[object Object]"` →
   **整篇零高亮且不报错**（静默失败，最难查的一类）。
   已在 markWords 加防御：`typeof w === 'string' ? w : w.w || w.word`。
2. **正文含 64402 处星号**（en 为主；zh 有 132 处单星斜体 = 法庭证词引文）。
   故事页不做剥离 → 会字面渲染。
3. **段落分隔符混用 `\n` 与 `\n\n`**，且同一篇里 en/zh 用法还不一致 → 中英对照错位。

### 追加：段落对齐深挖 —— 找到最优规则 13/20 → 15/20（20:2x）

不甘心只等用户重生成，深挖了一层，**根因定位到三条**：

1. **英文用单 \n 分段、中文用 \n\n 分段**（生成器不一致）。
   实测篇1：英文按 \n 切 = 94 段（== 中文 94 段），按 \n\n 切只有 3 段。
   → 转换时**必须把英文单 \n 提升为 \n\n**（前端 buildBilingualPairs 只认 \n\n）。
2. **混入 Markdown 场景分隔线 \**：中英同位置各 7 处，被 \ 包裹，
   会被当成一段 → 必须过滤。
3. **中文有「每句对话一行」的排版习惯，英文是整段合并**（篇11：英文1段 ↔ 中文5段）。
   ⚠️ **这条无法机械还原** —— 中文每个短句都语法完整（以 。！？」 结尾），
   试过句末标点判据：篇11 的 204 段里只有 4 段不合规（全是斜体引文），信号不可用。

切分规则实测对齐率：
- 中英都按 \n\n → 13/20
- 中英都按 \n+ → 14/20
- **英文按 \n、中文按 \n\n + 过滤 --- → 15/20（最优，已内置到 verify）**

所以 verify 现在报的「5 篇不齐」是**真问题**（篇 2/9/11/12/18），不是规则缺陷造成的假象。
篇 1/4/6 靠新规则救回来了。
