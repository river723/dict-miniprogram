## 真机报错根因（修正上面的"缓存"猜测）
用户发回真机 console：`[dictionary] buildDicts 失败 TypeError: (0,_storage.getActiveLibraryId) is not a function`。
真因：**`dictionary.js` 第 13 行用了命名导入 `import { getActiveLibraryId } from '../../services/storage'`**，
但 `storage.js` 是 `export default {}`（无任何命名导出），所以解构出来是 `undefined`。
之前"缓存"猜测是错的——这才是列表空白的真凶（onLoad/buildDicts 抛异常 → dicts 停留初始空数组）。
修法：删掉命名导入，改用默认导入 `StorageService.getActiveLibraryId()`（第 14 行已默认导入）。
⚠️ **教训：`storage.js` 永远是 `export default`，引用其成员一律走 `StorageService.xxx`，禁止命名导入。**
`libraries.js` 是 `export const/function` 命名导出，可命名导入。两者不要混。check_syntax 0 错误。

## 修：雅思词库点词报"未找到该单词"
用户反馈：在雅思词库点 `asthma` 提示"未找到该单词"。
根因：浏览页 `openWord` 只传 `word` 给详情页；详情页 `dictionary-word-detail` 一律走云端
`searchWorddict` 查考研词库，内置雅思纯词表词（如 asthma，已确认在 ielts.js 第 3 行）不在云端 → `notFound`。
修法：
- `dictionary-browse#openWord` 追加传 `&dictId=<dictId>`。
- `dictionary-word-detail#onLoad` 读 `dictId`，记 `localMode`/`localDictId`；`load()` 云端未命中时，
  若 `localMode && isInLocalLibrary(word)`（大小写不敏感）→ 渲染 **localOnly 视图**（显示单词 + 发音/TTS +
  "加入生词本"，并提示"纯词表暂无释义，联网后自动补全"），而非"未找到"。
- `isInLocalLibrary` 用 `getLibraryWords(dictId)` 做本地存在性判断；`load` 开头重置 `localOnly/notFound`。
- WXML 加 `wx:elif="{{localOnly}}"` 分支；`confirmAdd` 对本地词缺字段给空串/空数组兜底。
- 仍先试云端：若某本地词恰好也在云端考研库则显示完整释义（常见词兼得）。
check_syntax 0 错误。
