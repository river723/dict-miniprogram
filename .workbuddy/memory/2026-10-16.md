## 修：考研词库右上角显示"仅1000词"
用户问：为何考研词库（云端 all）右上角显示仅 1000 词。
根因：列表页 `dictionary#loadCounts` 与浏览页 `dictionary-browse#loadTotal` 都用
`pickWorddict({limit:1,seed:1}).candidates` 当总词数渲染。**但 `candidates` 不是库大小**——
它是 `cloudfunctions/worddict#pick` 自动配词算法的短路计数器（只扫 top 频率页、集满 200 即停，
或首页 <1000 即停），设计语义是"候选池是否非空"的布尔信号，绝不该当总数展示。
已验证源数据 `import-data/worddict-all.json` = **4801 条**（JSONL 每行一条），考研词库本应有 4801 词。
用户看到的"1000"≈首页 PAGE=1000 大小，说明当前部署的 worddict 云函数大概率是带 `candidates>=200`
早停之前的旧版本（旧版 candidates 数满首页 1000）。

修法（已落地，需重部署云函数才生效）：
- `cloudfunctions/worddict/index.js` 新增 `count` action：`db.collection(COL).count().total`（真实总数）。
- `miniprogram/services/worddict.js` 新增 `countWorddict()`。
- `dictionary.js#loadCounts`、`dictionary-browse.js#loadTotal` 改用 `countWorddict()`（不再误用 candidates）。
- 两处 import 由 `pickWorddict` 改为 `countWorddict`（browse 仍保留 `searchWorddict` 用于按字母/搜索）。
- check_syntax 0 错误。
- ⚠️ 重新部署 `worddict` 云函数后若仍显示 ~1000：说明云端 `worddict` 集合确实只导入了约 1000 条
  （导入不完整），需重跑 `scripts/import-worddict.mjs` 导入完整 4801 条——这属于数据问题，与显示 bug 无关。

## 修：雅思词库列表每行都显示"暂无释义"
用户报：雅思（内置纯词表）浏览列表每个词都刷"暂无释义"。
根因：`dictionary-browse#toRow` 对无 `definitions` 的词一律 `meaning='暂无释义'`。内置 ielts 词库
（`data/libraries/ielts.js` 是纯字符串数组，当初从 `.eudic` 只还原单词串、没带释义）整库无 definitions，
于是满屏"暂无释义"——是数据源特性，不是 bug，但很噪。
修法（纯 UX，已落地，check_syntax 0 错误）：
- `toRow(entry, localMode)`：本地纯词表且无释义 → `meaning:''`、`isLocal:true`（不再填"暂无释义"）。
- WXML 行：本地词显示静音标签「本地词 · 点按发音」并隐藏无意义难度/考频星；云端词无释义才落 `dbrow__meaning--empty` 灰字"暂无释义"。
- wxss 加 `.dbrow__tag`（accent 浅底圆角）+ `.dbrow__meaning--empty`。
- 词详情页 `dictionary-word-detail` 早已支持本地词：云端未命中走 `localOnly` 视图（可发音/加入生词本/联网补全）。
