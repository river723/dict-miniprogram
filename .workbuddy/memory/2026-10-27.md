## 控制台导入实操坑（已踩并已解决）
- 控制台导入器：① 文件名必须 `.json`/`.csv`（`.jsonl` 被拦 `invalid import filename`）；② 内容必须是 **JSON Lines（每行一个对象）**，数组形式报「格式不正确，请检查是否为 JSON Lines」。→ 已生成 `import-data/worddict-ielts-console.json`（.json 扩展名 + JSONL 内容）可直导。
- **导入成功**：4491 条成功、0 失败（任务详情确认）。
- **`prefix` 索引必须非唯一**：建索引若勾「唯一」会报 `E11000 duplicate key { prefix:"a" }`（首字母被几千词共用）。正确做法：字段 `prefix`、单字段升序、**不勾唯一**。删掉建失败的索引重建即可，数据不受影响。
- 剩余：权限设「所有用户可读」+ 重部署 `worddict` 云函数（认 lib=ielts）。

## 修复：生成文章保存后列表出现两条一模一样的文章
- 现象：趣味文章生成→保存，阅读页列表出现两条内容完全相同的文章（id 不同，是两条独立记录）。
- 根因：`article-generate.js#save` 用 `this.data.saving` 做防重入，但 `saving` 在 `await addArticle` 成功后即被 setData 回 `false`，而 `navigateBack` 还有 500ms 延迟；若返回失败页面不销毁、或用户在此期间再点一次，第二次点击会再 `addArticle` 一条一模一样的（uuid 不同）。→ 同一次生成被落了两条。
- 修复（双层）：
  1. `article-generate.js#save`：改同步实例标志 `this._saving` + `this._saved` 判定（`setData` 的 this.data 落到视图层是异步，不能作为可靠的同步重入锁）；成功置 `this._saved=true` 永久禁止本页再次保存，失败才释放 `this._saving` 允许重试。
  2. `storage.js#addArticle`：入参相同（标题+正文+目标词完全一致）时直接返回已有条目，不再新增——任何入口都不会写出重复。
  3. `storage.js#getArticles`：读时自愈，按「标题+正文+目标词」签名去重，仅在确有重复时写回（清掉用户已有的历史重复），正常无重复不触发落盘副作用。
- 验证：check_syntax 全过；node 模拟四场景（保存两次相同=1条 / 不同内容=2条 / 历史重复自愈=1条 / 正常读取无副作用）均正确。
