## 一、密钥绝不入库（GitHub secret scanning 会直接拒绝推送）

### 踩坑经过
2026-10-28 排障时把真实腾讯云 SecretId（`AKID` 开头）写进了 `.workbuddy/memory/2026-10-27.md`，
`git push` 被远端拒绝：

```
repository rule violations
secret scanning 拦截链接
```

### 判据
- **SecretId（`AKID` 开头）本身就是敏感凭证**。「只有 ID 没有 Key 危害小」是错觉 ——
  一样会被扫描器判定并拦下。
- **写日志只写「已能 echo 出来」，绝不写值本身。**
- `.workbuddy/memory/` **是要入库的**（项目记忆靠 git 同步给后续会话），不是本地临时目录。
  往里写东西前先想「这段会不会进公库」。

### 排查手法（一次扫全历史，含远端分支）
```bash
git grep -I -n -E "AKID[A-Za-z0-9]{20,}|sk-[A-Za-z0-9]{24,}" $(git rev-list --all) --
```
当时用它确认：全历史只有 1 处、且仅存在于**未推送**的提交里 → 只需脱敏当前文件，
**不需要重写 git 历史**（重写风险大得多）。

### 脱敏做法
- 正则替换 `AKID[A-Za-z0-9]{20,}` → `AKID***(已脱敏)`。
- 若含密钥的提交还没推送，最干净的做法是 `git reset --soft HEAD~1` 把两个提交合并成一个，
  让含密钥的 blob 彻底不可达。

### ⛔ 机器防护（已装）
- `.workbuddy/secret-scan.cjs`：扫暂存区新增行，命中下列任一即 `exit 1` 拒绝提交：
  腾讯云 SecretId / DeepSeek key / GitHub token / AWS key / 私钥块 / 微信支付 APIv3 密钥。
- `.githooks/pre-commit`：调用上面的脚本。
- **首次 clone 后要装一次**：
  ```bash
  git config core.hooksPath .githooks
  ```
  （`.githooks/` 因含本地路径不入库；扫描逻辑在入库的 `.workbuddy/secret-scan.cjs`。）

### 反例（本次亲身踩到两次）
写补记日志时把那串密钥又**原样抄了一遍** → 当场又被拦一次。
这条规则最容易被「我以为我知道」打败 —— **写的时候直接写「已脱敏」三个字，别复制粘贴值本身**。

## 二、数据导入（零密钥路线）

### 路线选择
| 路线 | 状态 |
|---|---|
| `npm run import:ielts -- --env=<ID>`（TCB 密钥） | ❌ **在本项目从未跑通** |
| 云开发控制台网页导入 | ✅ 实际走通的路 |

TCB 密钥路线失败原因：`cloud1-` 是微信云开发环境，**不认普通腾讯云 CAM 密钥** →
`INVALID_CREDENTIALS` / `MISSING_CREDENTIALS`。

### 控制台导入的三个坑
1. **只认 `.json` / `.csv`** → `.jsonl` 扩展名被拒（`InvalidParameter`）。
2. **内容必须是 JSON Lines**（每行一个对象），不是纯数组 —— 纯数组会报
   `Poll error, 导入数据格式不正确，请检查是否为JSON Lines格式`。
   ✅ 最终解法：**`.json` 扩展名 + JSON Lines 内容**。
3. **导入是追加模式** → 重复导会累加（4491 × 3 = 13473，每词三条）。

### 防复发：带 `_id` 的文件
`import-data/worddict-ielts-console.json`（gitignore，3.5MB，用
`scripts/build-ielts-only.mjs` 重新生成）：
- 4491 行，每行一个对象，**每条带 `_id` = word_id** → upsert 语义，再点几次也不会插重。
- 已校验：解析失败 0 / `_id` 重复 0 / 缺 `word` 0 / 不同 prefix 值 26。

### ⚠ 删集合的连带影响（最容易漏）
删集合会**连带删掉索引并重置权限** → 重导后必须：
1. 重建 `prefix` 索引，且必须是**非唯一**（prefix 是单词首字母，几千词共用一个值，
   勾「唯一」报 `DuplicateKey`）。
2. 重设集合权限为「**所有用户不可读写**」（官方文档术语叫「仅管理端可读写」，
   但控制台只显示「所有用户不可读写」；位置：点开集合 →「数据权限」→ 第 4 个单选项）。
   ⚠ **别设成「所有用户可读」** —— 那是过时指引，本项目前端 0 处直连数据库
   （全走云函数），开放客户端读权限只是白白开一个数据泄漏面，
   开放写权限更是**严重后门**：任何人拿到小程序都能改全站词库。
   ⚠ **也别设成「仅创建者可读写」** —— 这两个名字只差几个字，但后者客户端照样能
   往共享集合插文档（服务端读集合不带 `_openid` 过滤 → 插进去的内容对全站可见；
   admins 集能直接给自己发管理员）。
   五个选项的完整对照表见 `docs/管理员与鉴权.md` 第二节。
   **正确选项只有「所有用户不可读写」一个。**
3. `worddict` 云函数**不需重部署**（它只按 `lib` 参数查集合名，不依赖索引存在与否）。
4. 改完用小程序「设置 → 安全自检 → 检测集合权限」验证 9 个集合全绿
   （每个集合下方会显示「当前：所有用户不可读写」）。

### 零密钥播种流程（词库 / 内容）
- 词库：`npm run seed:build` → `seed/seed-data.js` → 部署 → 设置页「①②③」。
- 内容：`npm run content:build` → `contentseed/content-data.js` → 「④⑤」。
- **内联数据必须是与 index.js 同级的 .js**，该云函数目录要有 `package.json`。
- 默认超时 3 秒 → 批量须 `timeBudget` + 断点续跑；正式超时写 `config.json`（靠部署同步）。
- 当前 timeout：`ai`120 / `contentseed`60 / `seed`60 / `content`20 / `setup`20 /
  `worddict`20 / `admin`20 / `words`20 / `tts`10。

### ⚠ 各云函数职责边界
`seed` / `contentseed` **完全不涉及 `worddict_ielts`**（只管考研 `worddict` + `content_files`）
→ 雅思集合的导入/去重只能走控制台或 `scripts/import-worddict-ielts.mjs`。

## 三、云函数部署

### 一键部署
```bash
npm run deploy:cf                      # 部署 cloudfunctions/ 下全部云函数
npm run deploy:cf -- seed              # 只部署 seed
npm run deploy:cf -- admin seed setup  # 多个：空格分隔（也支持逗号 admin,seed）
npm run deploy:cf -- admin seed --dry  # 干跑：只解析参数不调 CLI
npm run deploy:cf -- --list            # 列出云端已有的云函数
CLOUD_ENV=xxx npm run deploy:cf        # 临时指定环境
```
- 走微信开发者工具自带的 CLI（`cli.bat`），省掉在 IDE 里逐个右键。
- 环境 ID 默认从 `miniprogram/constants/index.js` 的 `CLOUD_ENV` 读取，避免两处维护。
- **部署脚本按 `index.js` 探测函数目录** → 新增云函数目录会被自动发现，无需改脚本。

### ⚠ 参数分隔符：只能用空格或逗号，别用斜杠
`-- admin / seed` 里的 `/` 会被当成一个叫「/」的函数名 → CLI 去找
`cloudfunctions//` 的 index.js → 报 `cloudfunction entry file (index.js) not found`。
Git Bash 更会把 `/` 自动转成绝对路径（`C:/Users/.../PortableGit/`）。
- 脚本现在会**跳过**这类斜杠参数并提示，同时对**拼错的函数名显式报错退出**。
- 拿不准就先 `--dry` 干跑看一眼要部署哪几个。

### ⚠ 实现坑（脚本内已注明，别改回 spawnSync）
本机 `spawnSync(cmd)` 会稳定 EBUSY 失败，且 spawn 的 argv 引号转义会把
`"Program Files"` 路径拆坏。故统一用 `exec` + 整串带引号命令，是**已知唯一可靠路径**。

### 排查提示
1. 开发者工具必须在运行，且「设置 → 安全设置 → 服务端口」已开启。
2. 报 `FUNCTION_NOT_FOUND` 说明还没部署成功，不是代码问题。
3. 超时/网络错误可重跑；单个函数也可 `npm run deploy:cf -- <名字>`。

## 五、Git / GitHub 推送

### 代理坑
- git 全局 proxy 已清空，让它继承环境变量（`HTTP_PROXY` / `HTTPS_PROXY`）。
- **端口会变**：实测 4659 / 7019 / 12072。端口不通时逐个探测：
  ```bash
  for p in 4659 7019 12072; do
    curl -s -o /dev/null -w "%{http_code}\n" --max-time 6 -x "http://127.0.0.1:$p" https://github.com
  done
  ```
- 首轮 `CONNECT tunnel failed 502` 是隧道**瞬时故障**，稍后重试即通，不必改配置。
- 直接 `git push` 偶发报 `Recv failure` —— 也是隧道瞬断，**重试即通**，不要改配置。
- 本机 git 偏旧（PortableGit 1.2.0）：不支持 `git rm --stdin`；SSH 不可用。

### ⚠ 本机 Bash 的两个坑
- **缺 coreutils**（`ls`/`cat`/`grep`/`sed`/`mkdir` 等部分不可用）→ 目录/文件操作走 Node `fs`。
- **Bash 里嵌 `node -e` 写含反引号或 `$` 的代码会炸**（`Expected unicode escape`）→
  复杂逻辑一律写成 `.cjs` 脚本文件再跑。

  **限制集中在「AI 批量出题」，别按次数一刀切限流**。

### 虚拟支付
- 2026-04-01 起全终端强制；个人主体已可开（2026-08-31 起）。限额 **10 万/月**。
- 只做道具直购、不引入代币。
- 接入坑：两套签名（`paySig`=AppKey、`signature`=sessionKey）；
  **发货以「发货推送」为准**（前端回调会丢），`query_order` 兜底 + `wx_order_id` 幂等；
  金额单位「分」。
